# BancaTracker Enterprise v8.4.0

## Comparative Execution Intelligence & Operational Export Contract

**Status:** Approved governance contract; no implementation is introduced.

**Baseline:** v8.3.1 (`a66dd4ba78c8748a68d8867bedea209e195bd8c6`)

## 1. Objective and boundaries

v8.4.0 adds three additive, pure authorities:

1. Equivalent Elapsed-Day Comparison.
2. Branch Maturity Comparison and Movement.
3. Operational Full-Result CSV Export.

They consume existing governed data and contexts. They do not replace legacy operational authorities or add persistence, masters, source-data semantics, or a framework.

## 2. Equivalent Elapsed-Day Comparison

### Purpose and API

Proposed module: `js/analytics/equivalentElapsedDayComparison.js`.

```javascript
buildComparison({
  facts, performanceResult, periodContext, basePeriod, comparisonPeriod,
  dimension, authorityContext, throughDay
});
```

The authority is pure: it receives canonical accepted/governed facts plus existing Commercial Performance/Roll-up contexts and reads neither persistence nor the DOM.

### Existing authority reuse and scope

- `BancaTrackerCommercialComparison.validateComparisonPeriods()` validates selected months and reuses readiness conventions.
- `BancaTrackerDailyCommercialComparison.getDaysInPeriod()` supplies calendar/leap-year validity and the daily signed aggregation convention.
- `BancaTrackerCommercialRollups` supplies governed metadata, durable keys, and dimensions.

Supported dimensions are exactly `OVERALL`, `BANK`, `BRANCH`, `STATE`, `ZONE`, `BANK_REGION`, `BANK_ZONE`, `FGM_OFFICE`, `ASSIGNED_RM`, `CSM`, `ASM`, `ZSM`, and `NATIONAL_HEAD`. Governing scope is applied before daily aggregation. No independent Bank, Zone, State, hierarchy, LOB, or Product filtering is permitted. LOB/Product are excluded unless separately proven safe through an existing governed scope.

### Validity, horizon, and explicit through day

| Condition | Status |
| --- | --- |
| No governed periods | `NO_PERIODS` |
| Invalid or unavailable selected month | `INVALID_PERIOD` |
| Same base/comparison month | `SAME_PERIOD` |
| Either month has no valid dated fact | `NO_VALID_DATED_FACTS` |
| Valid comparison with invalid/missing date exclusions | `PARTIAL` |
| Fully valid comparison | `READY` |

A valid dated fact has canonical `monthKey`, integer `day` within its month, and numeric signed `premium`.

The architecture has no source-completeness/upload-horizon authority. It cannot distinguish zero business after a day from unavailable data after a day. Therefore v8.4 defines an observed-evidence horizon, not proof of a complete month:

```text
baseObservedHorizon       = highest valid transaction day in basePeriod
comparisonObservedHorizon = highest valid transaction day in comparisonPeriod
defaultThroughDay         = min(baseObservedHorizon, comparisonObservedHorizon)
```

Results must expose `horizonAuthority: "OBSERVED_VALID_TRANSACTION_DAY"`, both horizons, and effective through day.

Optional `throughDay` is permitted only if it is an integer >= 1, within both month lengths, and no greater than `defaultThroughDay`. Invalid or excessive input returns `INVALID_THROUGH_DAY`; it is never silently clamped.

### Result and reconciliation

For every day `1..effectiveThroughDay`, return:

```text
day
baseDailyActual / comparisonDailyActual
dailyAbsoluteChange / dailyGrowthPct / dailyDirection
baseCumulativeActual / comparisonCumulativeActual
cumulativeAbsoluteChange / cumulativeGrowthPct / cumulativeDirection
```

An in-horizon no-transaction day is zero activity. Evidence outside the horizon is unavailable and must not become zero. Summary includes through-day Actuals, `absoluteGap`, `growthPct`, `direction`, horizons, diagnostics, and reconciliation.

Growth follows existing Commercial Comparison rules: unavailable sides yield null movement; zero-to-positive yields signed amount and null percentage; zero-to-zero is flat with null percentage; negative bases preserve signed movement but yield null percentage.

```text
sum(baseDailyActual)       = baseThroughDayActual
sum(comparisonDailyActual) = comparisonThroughDayActual
final base cumulative       = baseThroughDayActual
final comparison cumulative = comparisonThroughDayActual
```

Totals must reconcile to the same governed scoped facts for Days 1 through `effectiveThroughDay`.

## 3. Branch Maturity Comparison and Movement

### Purpose and API

Proposed module: `js/analytics/branchMaturityComparison.js`.

```javascript
buildComparison({
  performanceResult, periodContext, selectedPeriods, dimension, authorityContext
});
```

The authority accepts exactly two or three chronological periods. It is additive and must not alter `BancaTrackerAnalytics.build()`, `BancaTrackerUtils.getBranchBand()`, or legacy Activation current-period semantics.

### Band, identity, and population authority

The authority must call `BancaTrackerUtils.getBranchBand(signedPremium)` and must not duplicate thresholds.

| Index | Band | Signed total |
| ---: | --- | --- |
| 0 | Zero | <= 0 |
| 1 | 1 - 14.9K | 1 to 14,999 |
| 2 | 15K - 24.9K | 15,000 to 24,999 |
| 3 | 25K - 49.9K | 25,000 to 49,999 |
| 4 | 50K - 99.9K | 50,000 to 99,999 |
| 5 | 1L - 1.99L | 100,000 to 199,999 |
| 6 | 2L+ | >= 200,000 |

Negative and zero totals remain in `Zero`.

Movement identity is governed durable `branchId`; display name is metadata only. Missing/unmapped durable identity is excluded from movement and reported diagnostically.

The population is governed commercial branch-period population, not legacy Activation observed branch names and not the full Branch Master universe. A branch-period participates only when represented by accepted governed Actual facts or an existing governed commercial reference branch-period that explicitly establishes zero activity. No fact and no governed reference is unavailable, not zero. Inactive Branch Master status is metadata only: it cannot erase facts or fabricate a zero period. A newly mapped branch is non-comparable until represented in both adjacent periods.

### Monthly distribution and adjacent movement

For each selected month return `periodKey`, `populationCount`, and every band with `band`, `orderedBandIndex`, `branchCount`, `percentageOfPopulation`, `signedPremium`, reconciliation, and diagnostics.

```text
sum(branchCount across bands) = eligible scoped branch population
```

Two periods produce one transition. Three periods produce only Month 1 -> Month 2 and Month 2 -> Month 3. Month 1 -> Month 3 is excluded.

Movement derives only from band rank:

```text
UPGRADED | DOWNGRADED | UNCHANGED | NOT_COMPARABLE
ZERO_TO_ACTIVE = Zero -> band index >= 3
ACTIVE_TO_ZERO = band index >= 3 -> Zero
```

One-sided branches return `BASE_ONLY` or `COMPARISON_ONLY` and `NOT_COMPARABLE`; they do not enter upgraded/downgraded/unchanged counts. Complete branch results expose identity, display metadata, both months, signed premiums, bands/indices, movement, special movement, presence, scope metadata, reconciliation, and diagnostics. UI, drill-down, and export consume these rows without recalculation.

## 4. Operational Full-Result CSV Export

### Principle and APIs

Proposed utility: `js/export/csvExport.js`. It is generic serialization/download infrastructure and owns no analytics, scopes, rankings, or business formulas.

```text
complete authority result -> presentation slice
complete authority result -> CSV export
```

Visible DOM rows must never be exported. Export handlers must not recompute analytics.

```javascript
serializeCsv({ rows, columns, includeBom, lineEnding });
downloadCsv({ csv, filename });
buildFilename({ datasetId, periods, scopeLabel, fallback });
```

### Serialization, download, and datasets

`columns` define explicit ordered keys, labels, and optional value functions. Caller row order is preserved; serializer never sorts.

- Default line ending: `\r\n`; UTF-8 BOM default: enabled.
- `null` and `undefined`: empty field.
- Numbers: ordinary non-localized JavaScript decimal representation.
- Booleans: `TRUE` / `FALSE`; dates are canonical caller-supplied strings.
- Values containing comma, quote, CR, or LF are quoted; embedded quotes are doubled.

Downloads remain offline/client-side:

```text
CSV -> Blob(text/csv;charset=utf-8) -> object URL
-> temporary download anchor -> revoke URL
```

Filename components are lowercase slugs: whitespace becomes `-`, unsafe characters are removed, repeated separators collapse, `all`/`overall` remain explicit, multiple periods use `-vs-` or `-to-`, and fallback is `bancatracker-export.csv`.

Each exportable view declares `datasetId`, analytical authority, complete row source, ordered columns, sorting authority, filename metadata, and enabled state.

Initial v8.4 candidates are Equivalent Elapsed-Day daily/cumulative results, Branch Maturity movement, and other new v8.4 complete-result views. Legacy Near Active, Inactive, Activation, Productivity, and Scorecard Top-N exports are deferred.

## 5. Scope, exclusions, and foundation

| Classification | Scope |
| --- | --- |
| Must | Two-month elapsed-day signed daily/cumulative comparison; through-day gap/growth; governed dimensions; two-month maturity comparison; bands; adjacent movement; Zero-to-Active/Active-to-Zero; complete movement result; CSV utility; export of new complete-result datasets |
| Should | Three-month maturity comparison; explicit through day; comparison table; maturity export; scope-aware filenames |
| Defer | Average Ticket Size; policy-count KPIs; historical hierarchy-as-of reconstruction; broad legacy Top-N export retrofit; export-everywhere framework; storage/master/schema work; Activation redesign |
| Excluded unless separately proven | LOB/Product scope |

Average Ticket Size is out of scope. The accepted PR import contract has no authoritative durable policy, certificate, proposal, or transaction identity; row count must not become ticket count. A future Policy/Transaction Identity Authority is required.

No large generic framework is approved. Reuse Commercial Rollups, Commercial Comparison, Daily Commercial Comparison, governed dimensions, and Commercial Performance UI patterns. Add only the two narrow authorities and CSV utility.

## 6. Acceptance contract

### Equivalent elapsed-day fixture

Use two months with horizons Day 8 and Day 10, an in-horizon zero-activity day, a negative adjustment, a zero-base denominator, Bank/Branch scopes, and invalid/missing dated rows.

Expected: default through day 8; the in-horizon no-transaction day is zero; negative Actual remains negative; zero-to-positive percentage is null; invalid evidence is diagnosed/excluded; daily sums reconcile to final cumulative and governed scoped through-day totals.

### Maturity fixture

Cover `-1`, `0`, `14,999`, `15,000`, `24,999`, `25,000`, `49,999`, `50,000`, `99,999`, `100,000`, `199,999`, and `200,000`. Include upgrade, downgrade, unchanged, Zero-to-Active, Active-to-Zero, explicit zero activity, one-sided branch, duplicate display names with distinct IDs, and unmapped identity diagnostics.

Expected: band counts reconcile to population; only both-period branches enter movement totals; one-sided branches remain returned but non-comparable; transitions follow band rank only.

### CSV fixture

Include commas, quotes, newlines, null, signed negatives, deterministic headers, a complete result larger than visible Top-N, caller-defined stable sort, and unsafe filename characters.

Expected: RFC-style escaping, stable ordered output, empty null fields, preserved signs, all authority rows exported, and deterministic sanitized filename.

## 7. Protected architecture

The following remain protected unless a later approved implementation contract proves a concrete blocker:

- `js/core.js`, `js/analytics.js`, `js/activation.js`, `js/productivity.js`, `js/scorecard.js`, `js/target.js`, and `js/csvProcessor.js`;
- canonical enrichment and reconciliation semantics;
- Branch and Employee Master authorities;
- hierarchy authorities, Workforce Deployment v2, and Legacy Branch Assignment compatibility;
- repository lifecycle, IndexedDB adapter, schema, and versioning.

No production module, UI, test, or persistence behavior is changed by this document.
