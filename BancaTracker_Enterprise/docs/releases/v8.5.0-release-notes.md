# BancaTracker Enterprise v8.5.0 — Operational UX, Data Trust & In-App Guidance

## Release Type

Additive, backward-compatible operational UX release.

## Baseline

- Release: v8.4.1
- Commit: `651c5669a77bce7998f61c34369d431e13433d94`

## Release Summary

v8.5.0 improves terminology, monetary presentation, Data Quality action guidance, day-wise comparison, full-result operational exports, and in-app guidance while preserving the analytical authorities and offline HTML, CSS, and Vanilla JavaScript architecture established by v8.4.1.

## What’s New

### 1. Day-wise terminology clarification

- Renames the user-facing view to **Equivalent Elapsed-Day Comparison** and its supporting table to **Equivalent Elapsed-Day Detail**.
- Uses **Base Month Daily Premium**, **Comparison Month Daily Premium**, and **Cumulative Premium** consistently.
- Explains that Base and Comparison months are evaluated through the same valid transaction-day horizon.

These are presentation changes only. Internal analytical fields, horizon rules, signed-premium treatment, precision, reconciliation, and calculation semantics are unchanged.

### 2. Standardized absolute-rupee presentation

- Displays confirmed absolute-rupee values with the ₹ symbol, Indian digit grouping, and zero fractional display digits.
- Improves containment and wrapping for large monetary values without clipping or ellipsis.
- Includes premium-per-observed-branch and premium-per-active-branch where they represent absolute rupees.

Formatting does not round or mutate source values. Calculations and CSV exports retain raw numerical precision. Percentages, counts, ratios, and Target values expressed in ₹ Cr retain their distinct governed formats.

### 3. Actionable Data Quality guidance

Data Quality findings now provide deterministic action guidance through four modes:

- **CORRECT** — correct a proven invalid source value using authoritative evidence.
- **VERIFY** — compare the source and governing reference before correction.
- **REVIEW** — investigate a signal that may represent a legitimate business event.
- **INFORMATION** — understand a scope or context condition where correction may not be required.

Guidance explains the issue, why it matters, what to check, the appropriate action, and the correction or review source. Findings do not automatically correct, delete, deduplicate, or otherwise mutate accepted data.

### 4. All Channels day-wise comparison

- Adds **All Channels** to the Bank-level Equivalent Elapsed-Day view.
- Aggregates the Bank comparison entity across all facts remaining within the applicable scope.
- Continues to support independently selected Base and Comparison months.
- Preserves signed premium values and the existing elapsed-day authority.

All Channels is an aggregate comparison view, not a new transaction or source channel.

### 5. Full-result Opportunity Ownership CSV

- Adds a CSV export to Opportunity Ownership.
- Keeps the visible operational table bounded to Top-100 rows.
- Exports the complete governed eligible result for the applicable current-period and global Bank scope.
- Preserves raw numeric precision, deterministic ordering, CSV escaping, and browser-local download behavior.

### 6. Branch Movement export discoverability and state safety

- Places the full CSV action alongside the Branch Movement heading.
- Keeps the visible movement table bounded to Top-100 rows.
- Exports the complete selected transition.
- Treats Movement Filter as presentation-only for the full export.
- Disables export safely when the selected result is empty, invalid, or stale.

### 7. Help, Manual & Glossary

Adds a ninth primary page with:

- Getting Started
- User Manual
- KPI & Field Glossary
- Interpretation Guide
- Understanding Filters & Scope
- Data & Master Reference
- Data Quality & Troubleshooting

The glossary supports safe case-insensitive search, category filtering, clear/reset behavior, and zero-result feedback. It reads configurable activation thresholds and published maturity bands at runtime, reuses the governed Data Quality action modes, operates fully offline, and does not depend on uploaded PR data. Search text is rendered safely through native DOM text operations.

## Architectural Guardrails Preserved

The release does not change configuration, CSV processing, core analytical context, analytical authorities, master or enrichment authorities, Target authority, Equivalent Elapsed-Day authority, Branch Maturity authority, or Commercial comparison, execution, priority, drill-down, and driver authorities.

The All Channels UI composes the existing governed `OVERALL` comparison using the same applicable scoped fact population. Export additions consume complete governed results and do not scrape rendered tables.

No runtime dependency, CDN, build pipeline, server component, or XLSX library was introduced.

## Deferred / Not Included

### Shared CSV formula-prefix hardening

Shared handling for text cells beginning with spreadsheet formula prefixes remains deferred to a separate security-governance change. Existing CSV serialization behavior is unchanged in v8.5.0.

### XLSX export

XLSX feasibility was assessed and is technically feasible, but implementation is intentionally deferred. Future value is strongest for Opportunity Ownership and Branch Movement. Adoption requires a separate dependency, licensing, security, browser-compatibility, performance, and offline-vendoring decision. No XLSX export or dependency is included in v8.5.0.
