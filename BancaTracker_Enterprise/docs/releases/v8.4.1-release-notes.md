## Corrective Scope

### 1. Production policy-date header compatibility

The PR importer now recognizes these explicit semantic aliases:

- `POLICY ISSUED DATE`
- `POLICY ISSUE DATE`

Both map only to the existing canonical accepted-row field `policyIssuedDate`. Matching remains case-insensitive with outer whitespace normalization. No fuzzy matching or arbitrary date-header synonyms were introduced. Supplying multiple recognized aliases is rejected rather than applying precedence.

### 2. Canonical date contract hardening

At least one recognized policy-date semantic header is required for a PR import. The approved header supplies `policyIssuedDate` to the existing Date Resolver, which derives canonical `monthKey`, Month, Day, and financial year.

No Month fallback was introduced. Raw Month and Day remain legacy/reference fields, and the policy-issued date through either approved header remains the sole canonical temporal source. Existing date formats and invalid-date behavior are unchanged.

### 3. Production-shaped Commercial regression

Regression coverage now exercises:

```text
POLICY ISSUE DATE CSV
→ CSV processor
→ core date authority
→ Commercial Performance
→ governed period context
```

The fixture validates Apr-26, Jul-26, Aug-26, and Sep-26 canonical period derivation, signed Actual reconciliation, absence of missing-month exclusions for valid rows, latest-Actual selection, and preservation of reference-only future periods.

### 4. Priority drill-down regression hardening

Reference Priority and Execution Priority are both covered using browser-like bubbling clicks against their rendered entity-name buttons:

```text
BANK A
→ ZONE
→ 2 child rows
→ READY
```

No product fix was required for priority drill-down. Entity-name buttons are the interactive controls; priority rows and metric cells remain display-only.

### 5. Protected architecture

v8.4.1 makes no analytical-authority changes to Commercial Performance, Commercial Rollups, Equivalent Day, Branch Maturity, or Commercial Execution authorities. It also does not modify canonical enrichment, Business Attribution, masters, hierarchy, Workforce Deployment, repository lifecycle, IndexedDB, or schema/storage.

## Security Governance

**SECURITY_HARDENING_AND_VAPT_REQUIRED**

Security hardening is intentionally outside this corrective release and must be handled as a dedicated subsequent iteration. Recommended scope includes imported-data DOM/XSS, CSV/formula injection, malformed or malicious CSV handling, IndexedDB/local-storage exposure, privacy/session behavior, CSP and security headers, GitHub Pages hosting constraints, dependency and supply-chain review, prototype/object-key attacks, oversized-file resilience, static security analysis, dynamic browser testing, and formal VAPT remediation and retesting.
