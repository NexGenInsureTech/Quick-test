## Release Summary

v8.6.0 introduces period-aware Activation eligibility governance, governed Target Seasonality, centralized CSV formula-prefix hardening, clearer Commercial Priority drill-down affordances, and aligned in-app help. It preserves the offline HTML, CSS, and Vanilla JavaScript architecture and keeps existing analytical authorities distinct.

## What's New

### 1. Historical / effective-dated Eligible Branch Universe

- Activation now resolves its denominator against an Eligible Branch Universe for the selected period.
- Explicit Branch Master effective dates support historical eligibility; eligible branches with no PR production remain represented as governed zero-denominator members.
- Legacy undated Branch Master records remain backward-compatible assumptions when their existing active and activation-eligible requirements pass.
- When governed period evidence is unavailable, configured totals remain a safe non-blended fallback.
- The Activation numerator remains business-derived from PR production.

Commercial and Maturity populations are unchanged. Branch Master membership does not create Maturity rows or Maturity Zero rows.

### 2. Governed Target Seasonality

- Annual Target remains the management objective, separate from monthly phasing.
- Target Seasonality governs fiscal-month weights through Bank-specific curves, Overall curves, and Bank inheritance from Overall where appropriate.
- When no applicable governed curve exists, the resolver safely uses equal monthly weights.
- Target Seasonality Master records persist in browser-local IndexedDB and are administered through Master Data Administration.
- Current-month Target uses the full governed monthly allocation; YTD Target uses the cumulative governed allocation.
- RRR remains the remaining annual gap averaged across remaining months; no daily Target proration is introduced.

Commercial Budget and Potential remain independent branch-period commercial reference data and are not changed by Target Seasonality.

### 3. CSV formula-prefix hardening

- Current governed CSV exports share a centralized serialization boundary.
- Spreadsheet-formula-risk text is protected at export time only.
- Numeric values and numeric-looking text retain their governed serialization semantics.
- Source data, governed records, and calculations are not mutated.

This is targeted CSV hardening, not a claim of complete spreadsheet security.

### 4. Commercial Priority-table affordance

- Reference Priority and Execution Priority entity controls have a compact, more discoverable visual cue.
- The accessible action name clearly identifies drill-down.
- Existing drill-down authority, non-interactive surrounding rows and metrics, and terminal Branch behavior are unchanged.

### 5. Help, Manual & Glossary alignment

The offline Help, Manual & Glossary now explains Target Seasonality, the Target versus Commercial Budget/Potential distinction, RRR, the Eligible Branch Universe and historical-period interpretation, Projected Shortfall, and Pace Gap Magnitude.

## Governed CSV Export Inventory

Current governed production CSV exports are:

1. Opportunity Ownership
2. Equivalent Elapsed-Day Comparison
3. Branch Maturity Distribution
4. Branch Movement

This list does not imply that every application table exports.

## Architecture Preservation

v8.6.0 remains offline and browser-first, built with HTML, CSS, and Vanilla JavaScript. It introduces no backend, CDN, runtime network dependency, or framework.

## Backward Compatibility

- Existing PR CSV and Branch Master data remain usable.
- Target Seasonality is additive.
- IndexedDB advances from version 2 to version 3 with an additive `targetSeasonality` store.
- Existing session Target settings remain usable.
- Absence of Target Seasonality resolves safely to governed equal-month fallback.
- Normal existing users have no mandatory migration action.
